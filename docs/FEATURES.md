# Feature inventory

Status terms are defined in the [documentation index](README.md). Status below is based on source inspection and the checks recorded in the improvement log.

| Feature                          | Inputs and outputs                                                                                        | Implementation and dependencies                                                       | Status and failure cases                                                                                                                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resume upload and extraction     | PDF, DOCX, or TXT up to 5 MiB → extracted text                                                            | `UploadForm.tsx`, `fileUtils.ts`; pdfjs-dist, mammoth                                 | **Implemented and verified** by ingestion tests. Unsupported, empty, oversized, signature-mismatched, or unreadable documents are rejected with a user-facing error. Image-only/scanned PDF OCR is not implemented.        |
| Conservative resume structure    | Extracted text → `ResumeSource` with `originalText`, sections, facts, unresolved fields, and evidence     | `fileUtils.ts`, `sourceSchema.ts`; Zod                                                | **Implemented and verified** by synthetic tests. Employers, job titles, dates, responsibilities, and achievements are currently marked unresolved rather than parsed into fact arrays.                                     |
| Job description entry            | User-entered text → analysis input                                                                        | `UploadForm.tsx`, `index.tsx`                                                         | **Implemented** by source inspection. A document upload/parser for job descriptions is not present. Server accepts 50–10,000 characters.                                                                                   |
| Gemini model discovery           | Same-origin GET → supported model options                                                                 | `pages/api/models.ts`, `src/api/models/gemini/`; server fetch, timeout and rate limit | **Implemented and verified** by production build; no dedicated upstream integration test. Safe generic errors are returned for unavailable/timeout responses.                                                              |
| Tailored analysis                | Resume text, job text, UI language, selected model → report with compact/detailed variants and match plan | `/api/analyze`, `prompt.ts`, schemas and response validation; Gemini SDK and Zod      | **Implemented and verified** by synthetic response/prompt tests and build. It is one Gemini generation, not multiple model stages. Exact-evidence checks do not independently prove every output field is source-grounded. |
| Report, edit, and strategy flows | Stored report/input → visual report, input recovery, strategy choice/retry                                | `pages/report.tsx`, `useReport.ts`, report components, `sessionData.ts`               | **Implemented** by source inspection. Draft migration from legacy localStorage occurs as individual keys are read. Storage is tab-scoped, not encrypted.                                                                   |
| Resume downloads                 | Selected resume version and locale → PDF or DOCX                                                          | `pdfGenerator.ts`, `docxGenerator.ts`, report header                                  | **Implemented** by source inspection. Export is client-side; no dedicated export test is present.                                                                                                                          |
| UI locale and theme              | Locale/theme preference → translated labels and styling                                                   | `IntlContext.tsx`, `translations.ts`, `ThemeContext.tsx`, `styles/theme.ts`           | **Implemented** by source inspection. Existing user-facing translations include English and Portuguese.                                                                                                                    |
